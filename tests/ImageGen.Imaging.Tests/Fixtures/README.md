# PNG decode test fixtures

External PNGs used to test `Png.Load` against files **our own encoder cannot
produce**. `Png.Save` only ever writes filter type 0, so round-tripping our own
output can't exercise the Sub/Up/Average/Paeth unfilter paths or RGBA — these
fixtures do.

| File | Format | Scanline filter | Pattern |
|---|---|---|---|
| `rgb_filter0.png` | 8×6 RGB | 0 (None) | `R=x*32, G=y*48, B=x*y*3` |
| `rgb_filter1.png` | 8×6 RGB | 1 (Sub) | same |
| `rgb_filter2.png` | 8×6 RGB | 2 (Up) | same |
| `rgb_filter3.png` | 8×6 RGB | 3 (Average) | same |
| `rgb_filter4.png` | 8×6 RGB | 4 (Paeth) | same |
| `rgba_filter0.png` | 5×4 RGBA | 0 (None) | `R=x*40, G=y*60, B=90, A=200` |

Each RGB file applies **one** filter type to every scanline, so the test's
per-filter coverage is exact. The expected pixels are recomputed from these same
formulas in `PngTests.cs`.

## Provenance / trust

These were generated by `generate_fixtures.py` (in this folder), which builds the
PNGs by hand (Python `zlib` only, filters applied explicitly) and then **verifies
each file with Pillow** — an independent, mature PNG decoder. A fixture is only
trustworthy if a third-party decoder agrees it encodes the intended pixels; that
check is the point. Regenerate with:

```
python generate_fixtures.py
```

(requires `Pillow`). If the pattern or sizes change, update the expected values in
`PngTests.cs` to match.
